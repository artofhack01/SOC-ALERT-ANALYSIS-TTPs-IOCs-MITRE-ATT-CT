1. SOC Alerts

   - A SOC alert is a notification generated by security monitoring systems when suspicious or potentially malicious activity is detected. SOC analysts investigate these alerts to identify threats, understand their impact, and determine whether an incident requires escalation.
     
:> Common Alert Examples:

- Suspicious IP Detected
- Multiple Failed Login Attempts
- Unusual Login Activity
- Malware Detection
- Suspicious Process Execution
- Unauthorized Access
- Possible Data Exfiltration
  
Alert Investigation: Identify the alert → Collect evidence → Analyse activity → Correlate events → Determine severity → Escalate if required.

First, an event must occur, like user login, process launch, or file download. Then, the system, like your OS, a firewall, or a cloud provider must log the event. 
After that, all system logs must be shipped to a security solution like SIEM or EDR. The SOC team can receive millions of logs per day from thousands of different systems, where most of the events are expected, but some require attention. Alert, a notification generated by a security solution when a specific event or sequence of events occurs, is what saves SOC teams from manual log review by highlighting suspicious, anomalous events, so analysts triage just dozens of alerts instead of millions of raw logs.

Examples: Suspicious IP addresses, malicious domains, file hashes, unusual files, and suspicious network connections.

SOC Example: When a suspicious IP address is detected, an analyst investigates its associated network activity, checks available threat intelligence, correlates related events, and determines whether the activity indicates a potential security incident.

IOC vs TTP: IOCs identify suspicious evidence, whereas TTPs explain the methods and behaviour behind an attack.

# Alert Prioritisation

Alert Prioritisation is the process of deciding which security alert should be investigated first.

Every SOC team has its own prioritisation rules. These rules are usually automated using SIEM or EDR tools.

### 1. Filter the Alerts

- Don't take alerts that are already assigned to another analyst.

- Avoid alerts that have already been investigated or resolved.

- Focus on new and unresolved alerts.

Goal: Avoid duplicate work.

### 2. Sort by Severity

Investigate alerts in this order:

1. Critical
2. High
3. Medium
4. Low

Start with critical alerts because they may indicate serious security threats that can cause major damage to the organization.

Example:

- Critical: Ransomware attack.
- High: Suspicious administrator login.
- Medium: Multiple failed login attempts.
- Low: Minor security policy violation.

### 3. Sort by Time

If multiple alerts have the same severity, start with the oldest unresolved alert and then move to newer ones.

Example:

- Alert A: Generated 3 hours ago.
- Alert B: Generated 5 minutes ago.

If both have the same severity and risk, investigate Alert A first because the suspicious activity may have been happening for a longer time.

Note: Never ignore a new critical alert just because an older alert is waiting.

### 4. Check Asset Importance

Check which system is affected.

For example:

- Domain Controller
- Production Server
- Database Server
- Employee Laptop

An alert involving a critical server may need more attention than an alert involving a normal test machine.

## Remember (Quick Revision)

| Priority factor | What to check |
| --- | --- |
| Filter alerts | New and unresolved alerts |
| Severity | Critical → High → Medium → Low |
| Time | Older alerts first (if risk is equal) |
| Asset | Which system is affected? |

Interview answer:

"Alert prioritisation means deciding which alert to investigate first. As a SOC Analyst, I filter duplicate and already assigned alerts, check severity, consider alert age, and identify the importance of the affected system. Then I investigate the highest-priority alerts first."

4. MITRE ATT&CK Framework

MITRE ATT&CK stands for Adversarial Tactics, Techniques, and Common Knowledge. It is a globally recognized knowledge base that documents real-world adversary behaviour and provides a structured understanding of how cyberattacks are planned and executed. It organizes attacker activities into tactics, techniques, and sub-techniques, helping security professionals understand attack objectives, identify malicious behaviour, and improve defensive capabilities. The Enterprise Matrix includes 15 tactics representing different adversary objectives: Reconnaissance, Resource Development, Initial Access, Execution, Persistence, Privilege Escalation, Stealth, Defense Impairment, Credential Access, Discovery, Lateral Movement, Collection, Command and Control, Exfiltration, and Impact. These tactics are not a fixed sequence; attackers may use different combinations depending on their objectives and attack methods. SOC analysts use MITRE ATT&CK to map suspicious activities, understand TTPs, investigate security alerts, support threat hunting, improve detection strategies, and build incident response playbooks. It also helps teams identify monitoring gaps and understand which attacker techniques their existing security controls can detect.

5. SOC Analyst – Practical Application

SOC analysts combine alerts, IOCs, and TTPs to investigate suspicious activities and understand potential attacks. MITRE ATT&CK provides a common framework
for mapping observed behaviour and improving detection and incident response.

Key Relationship:

- Alerts – What suspicious activity was detected?
- IOCs – What evidence indicates potential compromise?
- TTPs – How did the attacker operate?
- MITRE ATT&CK – How can the observed behaviour be classified and understood?
